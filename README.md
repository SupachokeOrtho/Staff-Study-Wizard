# Staff Study Wizard

เครื่องมือจัดทำ **การพิจารณาของฝ่ายอำนวยการ** แบบ 12 ขั้นตอน ใช้ HTML, CSS และ JavaScript ธรรมดา ไม่มี backend, analytics, AI, CDN, external fonts หรือ runtime dependencies

## เปิดใช้งานในเครื่อง

ต้องมี Python 3 สำหรับเสิร์ฟไฟล์แบบ static:

```sh
cd /workspace/Staff-Study-Wizard
python3 -m http.server 8000 --bind 0.0.0.0
```

เปิด `http://localhost:8000` ในเบราว์เซอร์สมัยใหม่ เช่น Chrome, Edge, Firefox หรือ Safari หากพอร์ตถูกใช้งาน ให้เปลี่ยนเป็นพอร์ตอื่น ไม่ต้อง `npm install` หรือ build โครงการ

ต้องเปิดผ่าน HTTP(S) ไม่ใช่ดับเบิลคลิก `index.html` ด้วย `file://` เนื่องจากแอปอ่านกฎและแม่แบบ JSON ตอนเริ่มต้น เมื่อโหลดหน้าและข้อมูลเสร็จแล้ว การกรอกข้อมูล การคำนวณ และการส่งออกทำงานได้โดยไม่ต้องเชื่อมต่อเครือข่าย การเปิดหรือรีโหลดหน้าใหม่ยังต้องเข้าถึง static host; MVP นี้ไม่มี service worker หรือการติดตั้ง PWA

## วิธีใช้งาน

1. กรอกข้อมูลโครงการ สภาวะพึงประสงค์ และสภาวะปัจจุบัน
2. วิเคราะห์ช่องว่าง ผลกระทบ สาเหตุที่เป็นไปได้ และสาเหตุที่แท้จริงพร้อมหลักฐาน
3. ระบุกิจ มุ่งประสงค์ และ END STATE ที่วัดหรือสังเกตได้
4. เสนอวิธีการแก้ปัญหาและประเมิน SFA ของทุกวิธีอย่างอิสระ
5. หากไม่มีวิธีผ่าน ให้ทบทวนข้อมูล; หากผ่านหนึ่งวิธี ข้ามไปข้อยุติ; หากผ่านหลายวิธี ต้องเปรียบเทียบ Superior Solution
6. สร้างเกณฑ์ทั้ง Effectiveness และ Efficiency กำหนดน้ำหนักเป็นสัดส่วนรวม `1.00` หรือตัวเลขเปอร์เซ็นต์รวม `100` โดยไม่ผสมหน่วย ให้คะแนนจำนวนเต็ม `1–5` ซึ่งคะแนนสูงหมายถึงดีกว่า
7. ตรวจทานวิธีที่เสนอและข้อยุติ ก่อนคัดลอก ดาวน์โหลด `.txt` หรือพิมพ์

คะแนนถ่วงน้ำหนัก = คะแนน × น้ำหนักที่ปรับเป็นสัดส่วน คะแนนรวมเต็ม 5 ตัวอย่างน้ำหนัก 60/40 และคะแนน 5/1 จะได้ 3.4 แอปแสดงคะแนนเท่ากัน และผู้ใช้สามารถปรับเกณฑ์หรือเลือกวิธีที่ผ่าน SFA อื่นในข้อยุติได้ วิธีที่ไม่ผ่าน SFA ไม่เข้าร่วมการเปรียบเทียบ ผล A จะผ่านได้เมื่อความเสี่ยงคงเหลือยอมรับได้

เลือกเปิดได้ทั้ง 12 ขั้นจากแถบเมนู แม้ข้อมูลก่อนหน้ายังไม่ครบ ปุ่มย้อนกลับและถัดไปไม่บังคับกรอกช่องจำเป็น และรีเฟรชแล้วยังคงอยู่ในขั้นที่เปิดไว้ ข้อมูลที่กรอกจะไม่หาย เมนูขั้นเปรียบเทียบเปิดอ่านคู่มือได้เสมอ แต่แสดงฟอร์มคะแนนเมื่อมีวิธีผ่าน SFA มากกว่า 1 วิธี ปุ่มถัดไปยังข้ามการเปรียบเทียบเมื่อไม่เข้าเงื่อนไข

หน้าตรวจทานรวมรายการข้อมูลที่ขาดและผลการพิจารณาที่ต้องแก้ พร้อมปุ่มกลับไปขั้นนั้น ส่งออกร่างได้ทุกเมื่อ โดยข้อความคัดลอก ดาวน์โหลด และพิมพ์จะขึ้น **ฉบับร่าง** หากยังไม่ผ่านการตรวจความครบถ้วน เมื่อกรอกครบป้ายนี้จะหายไป การเปิดข้ามขั้นไม่ถือว่าได้วิเคราะห์หรือผ่าน SFA แล้ว และแอปไม่ตัดสินความถูกต้องของหลักฐานแทนผู้ใช้

ข้อแถลงปัญหาและข้อยุติมีข้อความอัตโนมัติ เมื่อแก้เองแอปจะเก็บข้อความนั้นไว้แม้ข้อมูลก่อนหน้าจะเปลี่ยน โปรดตรวจทานหรือเลือกใช้ข้อความอัตโนมัติใหม่

## คู่มือ วิธีเขียน และเอกสารอ้างอิงในแอป

ทุกขั้นมีแถบ **เปิดสรุปเอกสาร · วิธีเขียนและตัวอย่างขั้นนี้** กดเพื่อดูสรุปหลักการ วิธีเขียนแต่ละช่อง ตัวอย่างจากสไลด์ ข้อควรระวัง และรายการตรวจตัวเอง แยกเปิด–ปิดหัวข้อย่อยได้ด้วยเมาส์หรือคีย์บอร์ด แอปจำหัวข้อที่เปิดไว้ระหว่างย้อนขั้นในหน้าต่างเดิม โดยไม่เขียนลงข้อมูลงาน

เนื้อหาประกอบด้วยสรุปหลักการ 28 หัวข้อ และแนวทางเขียน 45 หัวข้อ ครบ 12 ขั้น อ้างอิงจากไฟล์ที่ผู้ใช้ให้:

| เอกสาร | จำนวนหน้า PDF | ขอบเขตหลัก |
| --- | ---: | --- |
| แนะนำเพิ่มเติม.pdf | 4 | ความเชื่อมโยงสภาวะ ปัญหา เหตุ ข้อแถลง การกลั่นกรอง SFA และ Superior Solution |
| การพิจารณาของฝ่ายอำนวยการ อส งป 70 ครั้งที่ 1.pdf | 153 | หลักการ ข้อเท็จจริง ช่องว่าง สาเหตุ ข้อแถลงปัญหา และทางเลือก |
| การพิจารณาของฝ่ายอำนวยการ อส งป 70 ครั้งที่ 2.pdf | 210 | SFA ความเสี่ยง เกณฑ์ น้ำหนัก การอภิปราย ข้อยุติ และรูปแบบเอกสาร |

แต่ละสรุปมีลิงก์ไปยังหน้าอ้างอิงและคลังเอกสารต้นฉบับทั้งสามฉบับใน `references/` ใช้ **ลำดับหน้า PDF เริ่มที่ 1** ไม่ใช่เลขหน้าที่พิมพ์บนสไลด์ หาก browser ไม่รองรับ `#page=` ให้เปิดไฟล์แล้วไปยังหน้าที่ระบุเอง สำเนา PDF ตรงกับไฟล์ที่ผู้ใช้อัปโหลด ตรวจสอบด้วย SHA-256 ที่บันทึกในข้อมูลคู่มือ

แยกที่มาของตัวอย่างชัดเจน:

- **สรุปตัวอย่างจากเอกสาร**: สรุปโจทย์การเดินทาง การหารายได้เข้ารุ่น และ Decision Matrix ตามเลขหน้าที่ระบุ
- **ตัวอย่างสมมติ**: กรณีต่อเนื่องเรื่องลดระยะเวลาจัดทำรายงานของหน่วย ก. เรียบเรียงขึ้นเพื่อฝึกเขียน ตัวเลข บุคคล หน่วยงาน และคำสั่งในกรณีนี้ไม่ใช่ข้อมูลจริงจากสไลด์

คู่มือไม่เติมข้อมูลลงช่องกรอก ไม่เพิ่มข้อความในไฟล์ส่งออก และไม่แสดงในฉบับพิมพ์ เปิดดูสรุปทั้งหมดได้ offline หลังโหลดหน้าแล้ว PDF รวมประมาณ 45 MB โหลดเมื่อกดลิงก์เท่านั้น การอ่าน PDF offline ต้องดาวน์โหลดไว้ก่อน หากไฟล์คู่มือโหลดไม่ได้ แอปยังกรอก บันทึก และส่งออกงานได้

จุดที่เอกสารใช้รูปแบบต่างกันได้อธิบายในขั้นที่เกี่ยวข้องแล้ว เช่น จำนวนวิธีผ่าน SFA, ชื่อผนวก และความแตกต่างระหว่างข้อยุติกับข้อเสนอแนะ ขั้นข้อยุติแจ้งว่าสรุปอัตโนมัติของแอปเป็นบันทึกตรวจทาน ไม่ใช่ข้อความข้อยุติสั้นแบบทางการ ส่วนไฟล์ `.txt` ยังเป็นร่างเนื้อหา 10 ส่วน ไม่ใช่เอกสารราชการ 5 หน้าพร้อมผนวกตามสไลด์

## การจัดเก็บและความเป็นส่วนตัว

- ทุกช่องบันทึกลง `localStorage` ทันที ด้วย key `staff-study-wizard:v1` และคืนค่าหลังรีเฟรช
- จัดเก็บ **หนึ่งงานต่อ browser origin / profile** เท่านั้น การเปลี่ยนโดเมนหรือพอร์ตทำให้เห็นพื้นที่จัดเก็บคนละชุด
- ไม่มีการอัปโหลดข้อความ มีเพียงการร้องขอไฟล์ static ของแอปในตอนโหลดหน้า
- ข้อมูลไม่ได้เข้ารหัสโดยแอป และผู้ใช้เครื่อง / browser profile เดียวกันอาจเข้าถึงได้ การล้างข้อมูลเบราว์เซอร์หรือใช้โหมดส่วนตัวอาจทำให้ข้อมูลสูญหาย ควรส่งออกไฟล์เป็นระยะ
- `เริ่มงานใหม่` และ `ล้างข้อมูลทั้งหมด` ขอการยืนยันก่อนแทนที่งานปัจจุบัน
- ถ้าอ่านข้อมูลเก่าไม่ได้ แอปจะไม่เขียนทับข้อมูลนั้น ถ้าเต็มหรือจัดเก็บไม่ได้ จะแจ้งสถานะไม่สำเร็จแทนการแสดงว่าบันทึกแล้ว
- ถ้ามีการแก้ไขจากอีกแท็บ แอปจะหยุดบันทึกในแท็บเดิมเพื่อป้องกันเขียนทับ ให้ส่งออกงานในแท็บเดิมก่อนรีเฟรช
- `.txt` ใช้ UTF-8 พร้อม BOM เพื่อรองรับภาษาไทยในโปรแกรมอ่านไฟล์ทั่วไป ชื่อไฟล์เป็น `staff-study-[project-title]-YYYY-MM-DD.txt` ตามวันที่ท้องถิ่นของอุปกรณ์ ไม่รองรับการนำเข้าไฟล์ใน MVP
- การคัดลอกต้องได้รับอนุญาตจากเบราว์เซอร์ หากไม่ได้รับอนุญาต แอปจะเลือกข้อความให้คัดลอกเองหรือดาวน์โหลดแทน การพิมพ์ใช้หน้าต่างพิมพ์ของเบราว์เซอร์

## โครงสร้างโครงการ

```text
index.html                    โครงหน้าและจุดเชื่อม UI
css/style.css                 รูปแบบ desktop, mobile และ print
css/guide.css                 คู่มืออ้างอิงแบบเปิด–ปิด
js/app.js                     ฟอร์ม การนำทาง เหตุการณ์ และการอัปเดต UI
js/model.js                   ตรวจข้อมูล ตรรกะ SFA และคะแนนถ่วงน้ำหนัก
js/storage.js                 วันที่ แม่แบบงาน และ localStorage
js/export.js                  สรุปข้อยุติ เอกสาร และดาวน์โหลด UTF-8
js/guide.js                   โหลดและแสดงคู่มือแยกจากข้อมูลงาน
data/staff-study-rules.json    ลำดับขั้น ฟิลด์ คำแนะนำ ตัวเลือก และกฎตรวจข้อมูล
data/default-template.json    โครงสร้างงานเริ่มต้นและเวอร์ชันข้อมูล
data/staff-study-guide.json   สรุป วิธีเขียน ตัวอย่าง และเลขหน้าอ้างอิง
references/*.pdf              สำเนาเอกสารต้นฉบับทั้ง 3 ฉบับ
references/README.md          แหล่งที่มาและข้อสังเกตในการอ่านเอกสาร
tests/model.test.js           ทดสอบตรรกะและ persistence
tests/guide.test.js           ทดสอบความครบถ้วนของคู่มือ ลิงก์ และ SHA-256 ของ PDF
tests/browser_test.py         ทดสอบการใช้งานจริงด้วย Chromium
```

แยก storage, domain logic และ export เพื่อให้เพิ่ม AI review, PDF/DOCX หรือ storage adapter ในอนาคตได้ โดยยังไม่มีความสามารถเหล่านั้นในรุ่นนี้

## แก้ไขกฎ Staff Study

แก้ `data/staff-study-rules.json` เพื่อปรับข้อความช่วย ชื่อฟิลด์ ตัวเลือก SFA ประเภทเกณฑ์ ขอบเขตคะแนน หรือน้ำหนักรวมที่ยอมรับได้ ฟิลด์ `required` ควบคุมการตรวจความครบถ้วนของเอกสาร โดยไม่ล็อกการเปิดแต่ละขั้น แม่แบบข้อมูลใหม่อยู่ใน `data/default-template.json`

คงลำดับ 12 ขั้นตามหลักการที่กำหนดไว้ ป้ายชื่อและคำแนะนำแก้ได้โดยไม่แก้ JavaScript แต่การเพิ่ม/เปลี่ยนโครงสร้างฟิลด์ ลำดับตรรกะ หรือโมเดล SFA ต้องปรับ `model.js`, `app.js`, `export.js` และตัวตรวจข้อมูลใน `storage.js` ให้ตรงกัน พร้อมเพิ่มการย้ายข้อมูลเมื่อเปลี่ยนเวอร์ชัน การแก้กฎใช้กับการโหลดหน้าครั้งต่อไป ข้อความข้อยุติที่ผู้ใช้แก้เองจะไม่ถูกเขียนทับ

แก้เนื้อหาคู่มือใน `data/staff-study-guide.json`: `principles` เก็บสรุปพร้อม `refs`, `writing` เก็บวิธีเขียนและตัวอย่างสมมติ, `sourceExamples` เก็บตัวอย่างที่สรุปจากเอกสาร, `cautions` เก็บข้อควรระวัง และ `checklist` เก็บรายการตรวจตนเอง แต่ละ `ref` ใช้ document ID และเลขหน้า PDF จริง หากเปลี่ยนไฟล์ต้นฉบับ ให้ตรวจทุกเลขหน้าและปรับ SHA-256/จำนวนหน้าใน `documents` ด้วย ทดสอบด้วย `npm test` และ browser tests

## ทดสอบ

ใช้ Node.js 20 ขึ้นไปสำหรับ unit tests (ไม่มี npm dependencies):

```sh
npm test
```

Browser tests ใช้ Python, Playwright และ Chromium เป็นเครื่องมือพัฒนาเพิ่มเติม ไม่จำเป็นต่อการใช้งานแอป ติดตั้งใน virtual environment ตามต้องการ:

```sh
python3 -m venv /tmp/staff-study-test-env
/tmp/staff-study-test-env/bin/pip install playwright
/tmp/staff-study-test-env/bin/python -m playwright install chromium
```

เปิด static server ตามคำสั่งด้านบน แล้วรันจากอีก terminal:

```sh
/tmp/staff-study-test-env/bin/python tests/browser_test.py
```

ถ้าเครื่องมี Playwright อยู่แล้ว ใช้ `python3 tests/browser_test.py` ได้ ทดสอบด้วย browser ที่ติดตั้งในระบบผ่าน `CHROMIUM_PATH` หรือปล่อยให้ใช้ Chromium ที่ Playwright จัดการ ตั้ง `TEST_BASE_URL` หากใช้พอร์ตอื่น

ชุดทดสอบครอบคลุม workflow จริงทุกขั้น, validation, ไม่มี/หนึ่ง/หลายวิธีผ่าน SFA, น้ำหนักและคะแนน, การคงข้อมูลหลังรีเฟรช, การใช้งาน offline หลังโหลด, ดาวน์โหลด UTF-8, ข้อความที่แก้เอง, การลบและยืนยัน, พื้นที่จัดเก็บเสียหาย, ป้องกันแท็บเขียนทับ, escaping และหน้าจอมือถือ ภาพและไฟล์ทดสอบอยู่ใน `test-results/` ซึ่งไม่รวมใน Git การทดสอบปุ่มพิมพ์ตรวจการเรียกคำสั่งและ print CSS โดยไม่เปิด OS print dialog

การทดสอบคู่มือตรวจความครอบคลุมทุกขั้น ขอบเขตเลขหน้า ลิงก์ไฟล์ PDF ที่ใช้งานได้จริง การไม่โหลด PDF ล่วงหน้า การเปิดหัวข้อด้วยคีย์บอร์ด การไม่เปลี่ยน localStorage/ไฟล์ส่งออก และการไม่ขัดขวางแอปเมื่อคู่มือโหลดไม่ได้

## Deploy แบบ static

### GitHub Pages

1. Commit และ push ไฟล์โครงการไปยัง branch `main` ของ repository
2. ไปที่ **Settings → Pages → Build and deployment**
3. เลือก **Deploy from a branch**, branch **main**, folder **/(root)** แล้ว Save
4. เมื่อ GitHub deploy เสร็จ ให้เปิด URL ที่ GitHub แสดง

ไม่มี build command ใช้ path สัมพัทธ์ทั้งหมด จึงรองรับ project site ที่มีชื่อ repository ต่อท้ายโดเมน

### Cloudflare Pages / Vercel

เชื่อม repository เลือก framework **None / Other** และใช้โฟลเดอร์รากของโครงการเป็น static output ไม่ต้อง build และไม่ต้องเพิ่ม environment variables หรือ secrets บน Vercel ใช้ Other preset และ override output directory เป็น `.` หากระบบไม่ตรวจพบ static output โดยอัตโนมัติ

ตรวจข้อจำกัดขนาดไฟล์ของบริการก่อน deploy: PDF ครั้งที่ 2 มีขนาด 27,933,156 bytes (ประมาณ 26.64 MiB) ต้องใช้บริการที่รองรับไฟล์ขนาดนี้หากต้องการแนบต้นฉบับครบทั้งชุด อย่าตัดไฟล์หรือแก้ลิงก์โดยไม่ปรับข้อมูลเอกสารและทดสอบใหม่

การ deploy จะเผยแพร่ไฟล์แอปและ PDF อ้างอิงที่แนบใน `references/` ข้อมูลใน `localStorage` ของผู้ใช้ไม่ได้ถูกส่งไปด้วย
